# Прогноз ЛР1 до измерений

Модель: Qwen/Qwen3-4B-Instruct-2507, FP16, Tesla T4.
Сервер: vLLM 0.33.0, контекст 32768, enforce-eager.
Предварительные проверки: ответы содержат ровно 64 токена; два текста
при temperature=0 совпали. Это проверки реализации, не результаты опытов.
Журнал запуска: KV-кеш 38384 токена, Available KV cache memory 5.27 GiB.

1. Ожидаю роста TTFT с длиной запроса. На длинных запросах рост может
   оказаться быстрее линейного из-за затрат внимания. Повтор одинакового
   запроса с prefix caching должен уменьшить TTFT со второго раза.
2. Полное время ответа должно примерно линейно зависеть от числа выходных
   токенов. Оценка снизу: 8 GB / 300 GB/s ≈ 27 мс на токен. Ожидаю
   реальный TPOT примерно 30–80 мс: есть чтение кеша и дополнительные затраты.
3. Пределы задаю заранее: p90 TTFT ≤ 2 с и медиана TPOT ≤ 100 мс.
   Для goodput считаю запрос успешным, если он без ошибки, TTFT ≤ 2 с,
   TPOT ≤ 100 мс. Ожидаю выполнения пределов при 1–4 клиентах и превышения
   хотя бы одного предела при 16–32. Это прогноз, а не установленный результат.

Пропускная способность должна сначала расти, затем выйти на насыщение;
индивидуальные задержки должны увеличиваться. Для всех измерительных
запросов используются уникальные метки в начале и отдельный cache_salt.
В опыте с prefix caching три повтора имеют одинаковые текст и cache_salt.
Прогрев выполняется отдельно и не включается в итоговые показатели.
